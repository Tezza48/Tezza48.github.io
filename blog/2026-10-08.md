# Full Site Backend Overhaul
<em>2026 10 08 - 2026 10 17</em> (But started in June)

- Rewrote the whole site generator
- Site now uses templating system
- Pages dir files map directly to rendered files in dist
- Pages can reference outer "templates" to be wrapped, this can recurse to have a tree of dependencies
- Blogs get rendered direclty to raw partial HTML files which are loaded using Query String on the /blog-post endpoint
- Simple <code>StaticInsert</code> Hooks can inject pre rendered strings into any partial HTML, used for the latest blog preview on index.html and the blog post list on /blog
- It's not currently set up to be extended with plugins however the StaticInsert hook + mostly generic pages dir could support any arbitrary site content

I felt like additions to the site generator were becoming increasingly more difficult and it was not sitting well with me that fully recompiling the application was required to make any updates to HTML structure (also i thought it would be interesting to do the following) so i have totally restructured this static site generator!
It also lost focus on this refactor so had been making little bits of progress here and there but finally jumped in and completed it this week.
To recap, the previous implementation of this site was 2 parts:

- Statically generated HTML written with macros on top of a string builder (Cool and novel but a pain to use)
- Markdown blog entries

The site generator would run a bunch of Page functions which genrated HTML for static pages Plus HTML generated from the markdown files then write them to disc. This update implements a templating engine which transforms HTML from <code>/pages/*.html</code>, wrapping them in any templates from <code>/templates</code> (or technically any arbitrary relative URL) and outputs them to the dist dir. In addition to this there's a Blog step which parses markdown directly to the dist dir. Finally a system for injecting various pre-generated strings into pages or templates.

# Page transformation

Pages get loaded as HTML, the generator will look for any <code>&lt;StaticInsert name="templates/foo.html"$gt;</code> and recursively wrap the page content in templates until the they're all resolved.
I've added a few helpers:

- <code>tag_find(slice haystack, slice tag_name)</code> which will find a tag by matching the string and finding the <code>&lt;</code> and <code>&gt;</code> chars left and right
- <code>tag_split(slice haystack, slice tag_name)</code> which does the same but will return slices for the chunks before and after the tag as well as the slice containing the tag itself
- finally <code>tag_attrib(slice tag, slice attrib_name)</code> which finds any attributes by name in a tag.

<blockquote>The tag "api" is incredibly rhudimentary but works fine for the current scope</blockquote>

# Blog changes

Blog posts are now directly transformed to HTML and written as partial HTML to the dist dir.
The new <code>/pages/blog-post.html</code> page loads the requested partial from the query string and injects it into the page contents. This is a bit of a lazy move and could probably be abused but it does have the benefit of allowing the page harness to be cached and only loading blog post content over the wire.
It wouldn't be a big hassle to jsut output full HTML files for the posts if it's problematic to do it this way.

# String Injection

Finally to implement the blog post page as well as the blog preview on the homepage I've added an associative array mapping strings to strings which allows me to add any <code>&lt;StaticInsert name="" /&gt;</code> to a partial or templete anywhere, then register some arbitary string before pages are rendered to have that text injected anywhere.
For example the latest blog post can be seen here:

<div class="m-2 p-2 border border-white">
    <StaticInsert name="LatestBlogPost" />
</div>

and it will update over time as new posts are added. (I had to actually rewrite the majority of the tag query functions to correctly find tags without quitting early AND adding the static inserts to the blog part of the pipeline.)
