# A little markdown parser

<em>2026 04 25</em>

This is another direct upgrade to the site. I've implemented a very basic markdown renderer, it currently supports Headings, Paragraphs, Line Breaks and non nested Lists.

This is by no means a compliant implementation however it should be <em>good enough</em> for a bit. I'll explain in very light detail what i've done.

## The Parser

I've written a super basic single pass, line by line parser/transformer

* In a single loop, i iterate through tokens until hitting a newline <code>'\n'</code>
* Then we try to classify which tag to wrap the line in (h1, h6, p) by iterating/incrementing the line start (<code>char*</code>)
* For Lists, there's a tiny bit of state to track whether a new <code>ul</code> element is needed (and then whether we need the closing tag to end a list)
* Line breaks (<code>&lt;br&gt;</code>) get inserted if there's 2 or more repeated newlines
* Finally, the whole line gets rendered with <code>snprintf</code> using the classified element tag

It is a long way off from being fully compliant, some "nice to have" things would be backticks for code blocks (i'm hard coding "code" elements here, they're not html encoded either), *em* and **bold** support would go a long way and tables are super far off; i'm hoping that i don't need tables for a long time. 

## The Integration

Integration was a bit of a pain. I had to do a bunch of juggling around of existing code, loading from disc (now using <code>"glob.h"</code>) and rendering a dedicated 200 char preview from a slice of the markdown rather than slicing the rendered html, which avoids cutting through any open/closing elements.

The integration has also highlighted some friction in the current generator: the List implementation is a pain, there's a bunch of repetition to manipulate file paths, adding any new sections can be super fragile and requires directly adding code to the render loop.

There's also seemingly some memory leaking out... A problem for later.

I'd like to take a step back and intentionally design a code style/architecture that i'd like to follow, possibly a transformer pipeline or whatnot.

As for right now, i'm happy with the state of things
